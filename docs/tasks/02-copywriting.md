# Задание 2. Тексты страниц на EN, PL, RU по карте ключевых слов

## Контекст

Задание 1 выполнено: есть `research/keyword-map.md`, `research/keywords/*.csv`, `research/blog-plan.md`, `research/keyword-report.md`. Сейчас сайт показывает тексты-заглушки из типизированных модулей `src/content/fallback/{en,pl,ru}/`. Задача — заменить заглушки настоящими текстами, не меняя структуру данных (типы в `src/content/types.ts`). Вёрстка берёт всё из этих модулей, поэтому после правки тексты сразу видны на `localhost:3002`.

Прочитай перед началом: `CLAUDE.md`, `brief.md`, `docs/tasks/00-README.md`, `research/keyword-map.md`, `research/keyword-report.md`, `src/content/types.ts`, все файлы в `src/content/fallback/`.

## Голос и стиль

- От первого лица (Татьяна), спокойно, конкретно, без маркетинговых штампов («уникальный», «инновационный», «под ключ», «синергия»).
- Короткие абзацы; конкретика ритейла: SKU-уровень, option count, size curve, sell-through, OTB, price ladder, markdown, PLM-атрибуты, DAX-меры. Без цифр и названий, по которым вычисляется текущий работодатель.
- EN — британский английский (organisation, optimise). PL — естественный деловой польский, обращение на «Ty» или безличное — выбери одно и держи единообразно (рекомендация: безличные формы и «Ty» в CTA). RU — деловой русский, обращение на «вы».
- Для GEO/AEO: в начале каждой страницы услуги и статьи — 1–2 предложения прямого ответа на главный вопрос (что это, кому, какой результат). FAQ-ответы — 2–4 предложения, самодостаточные.
- Правила заголовков, конфиденциальности и образования — в `00-README.md`. Они обязательны.

## Что написать (для каждого языка)

1. `index.ts`: `ui` (навигация, кнопки, подписи форм — проверить естественность), `person`, `home` (все блоки, включая FAQ), `about` (кроме `credentials` — там тексты уже реальные, только вычитать), `servicesPage`, `caseStudiesPage`, `blogPage`, `contact`, `courses`, `templates`, `privacy`, `notFound`, `thankYou`.
2. `services.ts`: 6 услуг полностью — карточка, интро, проблемы, что входит, процесс, результаты, инструменты, FAQ, SEO.
3. Кейсы (`caseStudies.ts` / `work.ts`): тексты кейсов. Цифры результатов — оставить текущие плейсхолдеры и пометить `placeholder: true` там, где это поле есть; в отчёте перечислить, какие цифры нужны от владельца.
4. Блог (`blog.ts` / `work.ts`): рубрики + статьи по `research/blog-plan.md`. Минимум 3 полные статьи на каждом языке (800–1500 слов) с блоками `h2`, `p`, `list`, `formula`, `code` (DAX), `table` (типы — в `ArticleBlock`); остальные статьи — с полным описанием и SEO, тело можно оставить заглушкой, но пометить в отчёте.
5. `privacy`: реальная политика конфиденциальности под GDPR для этого сайта (форма: имя, компания, email, телефон, способ связи, текст; подписка на шаблоны и лист ожидания; cookies и аналитика только по согласию — GA, Clarity; хостинг Vercel; CMS Sanity; SMTP-почта). Контролёр данных — Tatsiana Bandziuk, Warsaw; email — `business@tatsianabandziuk.com` (оставить, если владелец не скажет иначе). Пометить в отчёте, что текст должен проверить юрист.
6. SEO каждой страницы (`seo.title`, `seo.description`) — из карты ключевых слов, с длиной до 60 / 155 символов.

## Слаги

Если в `research/keyword-report.md` принято решение переводить слаги PL/RU — **не** делать этого в этом задании без подтверждения владельца. Записать предложение в отчёт.

## Проверка

- `npm run typecheck` без ошибок.
- `npm run dev`, пройти все страницы на трёх языках: ничего не сломано, нет пустых блоков, нет текста длиннее вёрстки (заголовки карточек, кнопки, подписи ячеек формы).
- Скрипт-проверка (написать `scripts/check-content.ts`): длины `seo.title` ≤ 60 и `seo.description` ≤ 155; ни одного упоминания текущего работодателя (список запрещённых слов скрипт берёт из переменной `FORBIDDEN_TERMS` в `.env.local`, через запятую; сами слова в репозиторий не попадают; если переменной нет — скрипт завершается с ошибкой и просит владельца её добавить); «Бандзюк» не встречается; ни одного пустого заголовка.
- Отчёт `research/copy-report.md`: что написано, какие плейсхолдеры остались (цифры, рекомендации, фото, годы работы), какие решения нужны от владельца.
